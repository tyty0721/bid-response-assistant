# 设计与实现对应

本版按 docs/design.md 的供应商方向实现，采用一套 Skill 与小型本地脚本。设计稿是实施前的历史文档，其中“尚未实现”属于当时状态；当前实际验证以 test-report.md 为准。

| 设计能力 | 实现与实际边界 |
|---|---|
| 本地接收及来源锚点 | ingest.py生成原件哈希、PDF物理页和DOCX正文/表格位置；支持文件夹/ZIP，RAR需先可信解压 |
| 采购方式路由 | SKILL与路由参考；程序对方式、类型、法域做完整支持门控，其他输入保留分析但不能批准递交 |
| 要求及证据结构化 | 宿主智能体读全文生成record；逐块阅读台账、逐要求ID、条件/阶段/类型/来源；程序不冒充通用语义抽取器 |
| 证据匹配 | 脚本检查已记录的类型、主体、有效期、版本、引用及确认；语义充分性和真实性由宿主与企业核查 |
| 数值检查 | Decimal限价、合计、金额大写、有效期、保证金、代理费、低价关注；比例均来自项目记录 |
| 技术标记及评分 | 对结构化条款按标记计数并核对评分表；无对手数据不算实际价格分 |
| 草稿与交接 | DOCX、CSV、XLSX、JSON证据目录、MD审查报告和带哈希交接清单；通用审核稿，不保真回填平台模板 |
| 更正与批准 | diff按稳定ID列影响，清除批准；输入及来源快照改变使批准失效；输出独占创建保人工修改 |
| 递交边界 | 无外部采购动作，状态最多approved_for_manual_submission；真实回执人工核对归档 |
| 恢复与失败 | 新版本目录、可用中间结果、明确阻断；解析/OCR不足不伪造事实 |

为避免重复包装，设计中的validate_records/check_coverage/check_quote/diff/export合并为 bid.py 的子命令，共享校验逻辑。未建向量数据库、网站、API密钥或外部平台机器人。DOCX用代码模板直接生成，不引入docxtpl；XLSX用宿主Artifact Tool，CSV是可移植后备。

本版尚不包含：OCR模型、复杂扫描表格自动修复、全国采购方式规则库、企业身份认证、证据防伪、原采购平台模板无损回填和实际提交。技能可以利用企业批准的本地OCR或宿主视图继续处理，但这些能力没有作为本版已验证的自动功能宣传。

原设计要求的三份不同真实采购文件盲测、业务真值独立标注、两名业务人员验收尚未完成；当前是可运行工程版本，不能作为生产合规认证。合成留出案例、关键条款回归与单元测试分别报告，不给没有独立真值支撑的抽取准确率。
